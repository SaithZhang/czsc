## Vendor-neutral checkpoint

Read `CHECKPOINT.md` before resuming work, alongside the existing project rules and current-state documents. It records the saved branch, scope, validation limits, and continuation steps. At a meaningful milestone or before changing tools, update the existing project memory and checkpoint; commit source/rules/docs within the authorized scope and verify the pushed SHA. Keep private data, credentials, generated output, and full chat history out of Git. A checkpoint commit is not a production acceptance or deployment.
